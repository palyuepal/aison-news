# AIson publication contract

DAILY editorial work runs at 08:00 Asia/Hong_Kong, with a 09:00 same-day recovery. The existing Codex automation owns research; GitHub does not invent news. Use scheduled_for converted to Hong Kong as the edition date, falling back to started_at only if absent. Late startup is not a reason to skip. Missing or zero verified stories is a publishing incident, never a successful update. 1–10 verified stories remain permitted; the 2026-11-20 edition has ten. Never pad or backfill unverified historical editions.

Before writing, read main and all open same-day DAILY PRs. If a pair exists on main, verify/recover publication. If a PR exists, resume it. Only create daily/YYYYMMDD if neither exists. Commit only the daily and editorial source files together. LIVE continues to own content/live.json; no rewriting DAILY, generated output or unrelated UI. Avoid direct pushes to main.

`python tools/publication.py --date YYYY-MM-DD` validates paired schema, verification flags, ranks, date, IDs, editorial fields and featured top3Ids. The existing build, storyline, trust, deep read, search and PWA gates remain in force. The V3 check validates the pair and publication regression tests before its full render. No forced merges, bypass labels or admin merges.

Recovery runs on check completion and every 30 minutes from 08:07 to 23:37 Hong Kong. It only considers the repository owner's exact same-day daily branch, targeting main, with exactly the two source paths and neither already on main. It requires current-head build/trust/search/deep-read-quality/pwa, other checks/statuses and GitHub mergeability to be green. Failed runs get at most two retries (three attempts total); pending checks are never bypassed. Unexpected files, duplicates, existing main files or conflicts require reconciliation. Its privileged workflow never executes PR code. GitHub branch rules remain authoritative, including future required checks.

A recovery merge explicitly dispatches Pages, because a GITHUB_TOKEN merge does not generate a push run. Pages and sentinel are bounded and serialized. Pages validates the due source pair before spending time rendering. Before 08:00, yesterday is due; at or after 08:00, today is due. A missing due edition fails, rather than silently serving old news with a green deployment. This also means a LIVE deployment after the DAILY deadline can be held until the missing DAILY is resolved; the live source remains intact.

Pillow is pinned; CJK regular and bold fonts are cached. Fonts are fetched from the immutable official Noto Sans2.004 commit and checked against SHA-256 on every cache hit or miss; no apt mirror is involved. Downloads and Pillow installation have bounded network retries, per-operation limits, step limits and an overall job timeout. Render checks remain required.

Pages writes `data/publication.json` into the final artifact after all HTML patches. The source pair is snapshotted before deployment-time visual enrichment. It includes source hashes, edition, story count, top3Ids, commit, run URL, state=built, and hashes of actual latest/editorial payloads and both landing pages. `built` alone never claims public verification. Post-deploy and sentinel fetch the receipt and all four artifacts from aison.hk, compare source hashes, and verify artifact hashes. LIVE network failure fails public verification; no local fallback can report a successful publication.

The sentinel runs at 08:15/08:45 and every 30 minutes through 23:45. Missing/invalid source fails and opens or refreshes one dated incident issue. Valid source with stale public output gets one bounded redeploy per sentinel run, capped at two manual Pages dispatches per Hong Kong date; after a failed recovery, the issue stays open and the run fails. Recovered issues close only after public verification. Scheduled GitHub execution can be delayed; Codex usage limits/offline desktop can still stop research. Neither is concealed as success. Repository notifications and failed Actions runs are the alert channels; no external email is sent.

Operational handoff: source prepared → PR pending → checks passed → merged → built/deployed → public verified. Only the last state is published. Record PR, head and main SHA, Pages URL and public verification. If a run ends pending, the next recovery owns that same PR. Do not create duplicate editions. Historical gaps on November 17–19 remain unfilled pending research.

## Additional safeguards

All default freshness dates, including deployment-triggered checks after midnight, use the same 08:00 Hong Kong due-date function. At 00:00–07:59, yesterday remains due; a missing tomorrow edition must not create an early incident or consume recovery attempts. Scheduled monitoring remains 08:15 onward.

The sentinel verifies DAILY and the complete LIVE source objects, including body corrections, provenance URLs, active/verified flags and feed order. A LIVE-only mismatch therefore triggers the same bounded redeployment even if DAILY is already correct. LIVE source publication does not mean a fresh round of editorial research.

Check-completion recovery events are restricted to daily/** branches. Unrelated feature and main validations cannot generate redundant recovery jobs; manual and scheduled recovery remain available. These guards do not supply a missing research service or an independent external alert channel.
